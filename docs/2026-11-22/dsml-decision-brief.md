### 2.5 ผลของฝน: สองสเปกที่ต้องแยกกันอ่าน

มติของผู้ใช้คือ **เก็บ feature ฝนไว้ในโมเดล และรายงานว่าฝนมีผลน้อย** การตัดฝนออกจาก Final Champion เปลี่ยน WAPE เป็น 6.45 / 5.63 / 4.47 หรือต่างไป +0.12 / +0.05 / −0.05 จุด เครื่องหมายไม่คงที่และอยู่ในระดับสัญญาณรบกวน `[rain_ablation.csv]` `[rain_effect.csv]` `[online_replay/README.md]`

มีผลการถดถอยสองชุดที่ใช้สเปกคนละแบบ ทั้งคู่สื่อว่าฝนมีผลน้อย แต่**ห้ามนำค่า ΔR² มาวางเทียบกันตรง ๆ** เพราะตัวแปรตามและการควบคุมต่างกัน `[online_replay/README.md]` `[HYPOTHESES.md]`

| | H1 ใน HYPOTHESES.md (แนะนำให้ใช้เป็นหัวข้อหลัก) | รายงานของ Webber ใน rain_effect.csv (ชุดทดสอบความทนทาน) |
|---|---|---|
| ตัวแปรตาม | ระดับ log(arrivals) | การเติบโต YoY แบบ log คือ log(Y / Y₋₁₂) |
| ตัวควบคุม | province FE + calendar-month FE + log(lag 1) + log(lag 12) | โมเมนตัม log(lag1 / lag13) เท่านั้น **ไม่มี fixed effects** |
| ตัวแปรฝน (ที่ใช้พยากรณ์ได้) | `rain_lag_1` เป็น มม. | การเปลี่ยนแปลงฝนแบบ log YoY ที่กลายมาแล้วหนึ่งเดือน |
| ตัวอย่าง | ปี 2019, 2024, 2025 (n = 2,695) | ปีเดียวกัน n = 2,695 |
| ผล | t = −0.35, **p = 0.73**, ΔR² ถูกบันทึกเป็น **0.00005 pp**, ผลของ IQR (185.3 มม.) ≈ −0.13% (ช่วงเชื่อมั่น 95% −0.88% ถึง +0.62%) | **ΔR² = 0.0006** (0.06 pp), สัมประสิทธิ์ 0.0020, **p = 0.058** (province-clustered) |
| แหล่งที่มา | `[HYPOTHESES.md]` H1 | `[rain_effect.csv]` `[online_replay/README.md]` |

คำอธิบายว่าทำไม ΔR² ต่างกันมาก: โมเดลระดับของ H1 พร้อม fixed effects อธิบายความแปรปรวนได้แล้ว 99.6% (base R² = 0.99595) จึงเหลือ ΔR² จริงประมาณ 5×10⁻⁷ คำว่า "0.00005 pp" ใน HYPOTHESES.md คือค่านี้คูณ 100 ไม่ใช่ข้อขัดแย้งกับ ΔR² 0.0006 ของสเปกอัตราเติบโตที่ควบคุมน้อยกว่า `[online_replay/README.md]`

ฝนเดือนเดียวกัน (ใช้บรรยายเท่านั้น ไม่ใช่ input ของโมเดล): H1 พบว่ามีนัยสำคัญ p < 0.0001, ผลของ IQR = −1.66% `[HYPOTHESES.md]` ฝั่ง `rain_effect.csv` พบว่าควินไทล์ที่ฝนตกมากที่สุดมีจำนวนนักท่องเที่ยวน้อยกว่าควินไทล์ที่แห้งที่สุดประมาณ 2.0% (บรรยาย) `[rain_effect.csv]`

### 2.6 สมมติฐาน H1–H6 และ H3b

การทดสอบเป็น Diebold-Mariano บนผลรวมความคลาดเคลื่อนสัมบูรณ์รายเดือน มี HLN correction, t(11), ด้านเดียว ยกเว้น H1 / H5 ที่เป็น cluster-robust t และ H4 ที่เป็น difference-in-differences ตัวเลข H1–H6 มาจาก `run_hypotheses.py` ส่วน H3b ถูกรันใหม่บน Final Champion (C0, E2, eta 5) ผล eta 10 เดิมเก็บเป็นเชิงอรรถ ข้อสรุป accept / reject ที่ระดับ 5% ไม่เปลี่ยน `[HYPOTHESES.md]`

| สมมติฐาน | ผลย่อ | p-value | ข้อสรุป |
|---|---|---|---|
| H1 ฝนที่กลายมาแล้ว | t = −0.35, ΔR² = 0.00005 pp, ผลของ IQR = −0.13% | p = 0.73 | ไม่ reject H0: ไม่มีนัยสำคัญ และขนาดผลเล็กมาก |
| H1 ฝนเดือนเดียวกัน (บรรยาย) | t = −4.75, ผลของ IQR = −1.66% | p < 0.0001 | มีนัยสำคัญ แต่ไม่ใช่ผลพยากรณ์ |
| H2 RF logdiff เทียบ naive ปี 2023 | WAPE 19.97% เทียบ 32.72%, t = −3.54 | p = 0.002 | RF ดีกว่าอย่างมีนัยสำคัญ |
| H2 RF logdiff เทียบ naive ปี 2025 | WAPE 4.83% เทียบ 5.48%, t = −1.63 | p = 0.066 | ยังไม่ถึงนัยสำคัญ |

### 3จ. ช่องว่างของ Champion เทียบ RF logdiff ปี 2025 ยังไม่มีนัยสำคัญ (p = 0.15) ความซับซ้อนที่เพิ่มมาคุ้มหรือไม่

**บริบท.** Final Champion ชนะ seasonal naive อย่างมีนัยสำคัญทั้งปี 2023 (p < 0.0001) และปี 2025 (p = 0.003) แต่เมื่อเทียบกับ RF logdiff รายเดือน ซึ่งเป็นโมเดลเดี่ยวที่เรียบกว่า ชนะอย่างมีนัยสำคัญเฉพาะปี 2023 (p = 0.005) ส่วนปี 2024 p = 0.12 และปี 2025 p = 0.15 ยังไม่ถึงนัยสำคัญ ช่องว่างปี 2025 คือ 4.52% เทียบ 4.83% `[HYPOTHESES.md]` H3b ความซับซ้อนที่เพิ่มมาคือ EWA สองผู้เชี่ยวชาญ, feature `exp_lr_recent`, และการเลือก eta / COVID variant บนปี 2024 คุณค่าที่ชัดอยู่ที่ปีผิดปกติ (ปี 2023 ลดจาก 19.97% เหลือ 6.34%)

**ตัวเลือก**

1. เก็บ Champion แบบ EWA ไว้ เพราะทนทานในปีผิดปกติ และยังชนะ naive อย่างมีนัยสำคัญในปีปกติ โดยสารภาพตรง ๆ ว่าปี 2025 ยังไม่ชนะ RF logdiff อย่างมีนัยสำคัญ
2. ถอยกลับไปใช้ RF logdiff รายเดือนเป็น Champion เพราะปีปกติแทบไม่ต่างกันอย่างมีนัยสำคัญ และโมเดลเรียบกว่า
3. เก็บ Champion แต่ลดความซับซ้อนบางส่วน (เช่น คง EWA แต่ตัดสิ่งที่ปี 2025 ไม่ช่วยอย่างมีนัยสำคัญ) ซึ่งต้องกำหนดขอบเขตเพิ่มถ้าเลือกทางนี้

**ข้อดี / ข้อเสีย**

### 3ฉ. จะนำเสนอผลของฝนอย่างไร และจะยกสเปกไหนเป็นหัวข้อหลัก

**บริบท.** ผู้ใช้ตัดสินใจแล้วว่าให้เก็บฝนไว้ในโมเดล และรายงานว่าฝนมีผลน้อย ไม่ใช่ว่า “ไม่มีผล” หรือ “ช่วยได้” `[online-ml-replay-2025-plan.md]` มีสองสเปกตามส่วนที่ 2.5 ค่า ΔR² ไม่เทียบกันตรง ๆ ได้

**ตัวเลือก**

1. หัวข้อหลักใช้ H1 (มี fixed effects, โมเดลระดับซึ่งใกล้โมเดลพยากรณ์): p = 0.73, ΔR² = 0.00005 pp, ผลของ IQR ≈ −0.13% แล้ววางสเปกอัตราเติบโตของ Webber (ΔR² 0.0006, p = 0.058) เป็นชุดทดสอบความทนทาน พร้อมตารางตัดฝนของ Champion (+0.12 / +0.05 / −0.05 จุด) *(แนะนำใน README ของงาน replay)*
2. หัวข้อหลักใช้สเปกของ Webber (p = 0.058 ใกล้เส้น 5%, ΔR² 0.0006)
3. วางสองค่า ΔR² ไว้ข้างกันในสไลด์เดียวกันโดยไม่อธิบายความต่างของสเปก

**ข้อดี / ข้อเสีย**

- ข้อ 1 สอดคล้องกับโมเดลระดับที่มีการควบคุมมากกว่า และไม่ทำให้ผู้ฟังเข้าใจผิดว่า 0.00005 กับ 0.0006 เป็นปริมาณชนิดเดียวกัน
- ข้อ 2 สื่อสารง่ายกว่าในหน่วย ΔR² ปกติ แต่ควบคุมน้อยกว่า และ p = 0.058 อาจถูกอ่านว่า “เกือบมีนัยสำคัญ” มากกว่าความเป็นจริงของขนาดผล
- ข้อ 3 มีโอกาสทำให้สับสนสูง ไม่ควรใช้

**คำแนะนำของ PM:** เลือกข้อ 1 ตามที่ README แนะนำ และใช้ประโยคหลักว่า “ฝนมีผลน้อย” ตามมติของผู้ใช้ อย่าใส่สองค่า ΔR² ไว้ข้างกันราวกับเทียบกันได้

**ผลกระทบต่อสไลด์:** สไลด์ 6 วางหัวข้อหลักเป็น H1 อยู่แล้ว และตัดคำบรรยายของกราฟที่ยังใช้สเปก 0.0006 ออก `[slides-plan.md]` ถ้ามติเป็นข้อ 2 ต้องแก้หัวข้อและตารางของสไลด์ 6

## 5. ขั้นตอนถัดไปหลังมีมติ

1. ทีม DS/ML กรอกตารางในส่วนที่ 6 แล้วส่งกลับ

3. Tester ตรวจซ้ำบนหัว commit ใหม่ แล้วรายงานผล โดยเฉพาะ DQ, การยิงของ ADWIN หรือข้อความข้อจำกัดที่เขียนชัด, ลำดับของเกต, และเทส leakage / e2e
